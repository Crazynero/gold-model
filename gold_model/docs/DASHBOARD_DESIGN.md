# 黄金预测Dashboard — 前端设计方案

## 整体架构

```
前端（单页HTML）
    ↕ WebSocket / HTTP
后端API（FastAPI/Flask，封装V4脚本）
    ↕
V4 Python脚本 + 数据文件
```

技术选型：纯HTML+JS+Chart.js+ECharts，后端FastAPI封装脚本调用。
部署方式：本地启动，浏览器访问。

## Tab 4: 人工补充输入（核心交互功能）

这是设计的重点——让用户输入模型看不到的信息。

### 4.1 事件日历补录
| 输入项 | 类型 | 说明 |
|---|---|---|
| 重大事件标记 | 下拉+日期 | 选中日期标注"美联储鹰派/鸽派""地缘冲突升级""央行购金公告"等 |
| 自定义事件 | 文本+日期 | 用户描述事件内容，标注影响方向（利多/利空） |

### 4.2 市场观点输入
| 输入项 | 类型 | 说明 |
|---|---|---|
| 美联储政策预期 | 滑块(-5~+5) | -5=大幅宽松, +5=大幅紧缩 |
| 通胀预期 | 滑块(0~10%) | 用户对未来1年CPI的判断 |
| 地缘风险等级 | 滑块(1~10) | 1=和平, 10=全面战争 |
| 美元走势判断 | 滑块(-5~+5) | -5=大幅贬值, +5=大幅升值 |
| 个人风险偏好 | 滑块(1~5) | 1=极度保守, 5=极度激进 |

### 4.3 央行购金手动补录
| 输入项 | 说明 |
|---|---|
| 月度央行购金量(吨) | 用户从世界黄金协会月报手动输入 |
| 数据日期 | 月底日期 |
| 自动计算 | vs 去年同期变化率，vs 5年均值偏离度 |

### 4.4 模型参数调整
| 参数 | 范围 | 默认 |
|---|---|---|
| 预测周期 | 5/10/20/60日 | 20日 |
| 概率阈值(做多) | 0.5~0.8 | 0.65 |
| 概率阈值(做空) | 0.2~0.5 | 0.35 |
| Vol靶向 | 10%~25% | 15% |
| 止损阈值 | 3%~15% | 8% |
| 仓位上限 | 50%~200% | 100% |

### 4.5 综合预测调整面板
- 左侧：模型原始信号（灰色）
- 中间：用户调整项（蓝色滑块）
- 右侧：调整后信号（绿色）
- 底部：调整说明——显示哪些用户输入改变了模型信号，改变了多少

### 调整逻辑
```
最终概率 = 模型概率
         + 美联储预期调整 (-5~+5 → ∓10%)
         + 通胀预期调整 (偏高→+5%, 偏低→-5%)
         + 地缘风险调整 (1~10 → +0~10%)
         + 美元判断调整 (强美元→-5%, 弱美元→+5%)
         + 事件标记调整 (利多事件→+5%, 利空→-5%)
         × 风险偏好系数 (0.5~1.5)
最终概率 = clamp(0%, 100%)
```

## 交互流程设计

### 场景1：用户每周查看信号
1. 打开网页 → 自动加载最新一次运行结果
2. Tab1总览 → 看当前信号+多周期概率
3. 如果信号有变化 → 底部提示"上次信号是X，本次变为Y"

### 场景2：用户想补充自己的判断
1. Tab4 → 输入美联储预期（比如+3=偏鹰派）
2. 输入地缘风险（比如7=较高）
3. 点"重新计算" → 右侧实时显示调整后的信号
4. 如果调整后信号从"空仓"变成"做多" → 提示"你的输入使信号转为看多"

### 场景3：用户想重新跑模型
1. Tab5 → 点"重新生成"
2. 进度条+日志实时显示
3. 完成后自动刷新所有Tab

### 场景4：用户想回测不同参数
1. Tab4 → 调整概率阈值/Vol靶向
2. 点"回测" → 后端用新参数重跑策略部分（不重新训练ML）
3. Tab3 → 显示新参数下的策略表现

## 技术实现方案

### 后端API（FastAPI）
```
GET  /api/latest          → 最新一次运行结果（全部数据）
POST /api/regenerate      → 触发重新生成（返回task_id）
GET  /api/status/{task_id} → 查询执行状态+日志
POST /api/adjust          → 提交用户调整参数，返回调整后信号
POST /api/backtest        → 提交参数，返回回测结果
GET  /api/data/factors    → 因子原始数据
GET  /api/data/charts/{name} → 图表图片
GET  /api/history         → 历史运行记录
```

### 前端（单HTML文件）
- 纯HTML+CSS+JS，无需构建工具
- Chart.js：净值曲线、回撤、概率柱状图
- ECharts：K线图、雷达图、热力图
- 响应式布局，支持移动端

### 数据存储
- `runs/` 目录：每次运行一个子目录，包含Excel+图表+JSON摘要
- `user_inputs/` 目录：用户手动输入的事件和参数（JSON）
- `history.json`：运行历史索引

## 设计原则

1. **模型输出是参考，不是命令**——所有模型信号都用灰色/浅色显示，用户调整后的信号用高亮色
2. **透明度**——每个信号都能追溯到哪些因子贡献了多少
3. **不替用户做决定**——只提供信息和建议，最终操作由用户决定
4. **快速反馈**——用户调整参数后1秒内看到结果变化
5. **可追溯**——所有运行记录和用户输入都保存，可回溯
