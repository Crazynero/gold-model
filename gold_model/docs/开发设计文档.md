## 一、系统全景

### 1.1 一句话定位

基于 25+ 宏观/市场因子的机器学习黄金方向预测系统,V5 主管道每日生成"看多概率 + 仓位建议",Vue3 单页前端可视化,FastAPI 后端提供数据与交互。

### 1.2 架构拓扑

```
┌─────────────────────────────────────────────────────────────────┐
│                       数据源层(八层 fallback)                       │
│  yfinance → 新浪美股 → 东方财富 → 新浪期货 → 腾讯外汇                │
│  → CBOE → FRED → 代理因子(每 ticker 独立降级)                       │
└──────────────────────────────┬──────────────────────────────────┘
                               │ 24 tickers + 7 FRED 序列
                               ▼
┌─────────────────────────────────────────────────────────────────┐
│              主管道 gold_factor_v5.py(2551 行线性脚本)               │
│  采集 → 因子工程(41→25) → 标签 → Regime → Walk-Forward 训练           │
│  → 多周期集成 → V3.0-E 仓位策略 → 回测 → Holdout 验证                 │
│  → 当前预测 → 写 8 图 + Excel + JSON + SQLite + 漂移快照              │
└──────────────────────────────┬──────────────────────────────────┘
                               │ 写入产物
                    ┌──────────┼──────────┬────────────┐
                    ▼          ▼          ▼            ▼
              web/*.json   outputs/   data/*.json   data/*.db
              (前端数据)   (图表/PDF)  (缓存/状态)   (SQLite历史)
                    │                                    │
                    ▼          ┌─────────────────────────┘
┌─────────────────────────────┴──────────────────────────────────┐
│              FastAPI 后端 api_server.py(端口 8000)                 │
│  静态托管 HTML + /api/* 路由 + WebSocket 推送 + 文件监听             │
│  数据来源:JSON(mtime 缓存)+ SQLite(db 单例)                       │
└──────────────────────────────┬──────────────────────────────────┘
                               │ HTTP / WS
                               ▼
┌─────────────────────────────────────────────────────────────────┐
│           Vue3 前端(单 HTML,4 大区 19 个 Tab)                      │
│  数据加载三层:API → fetch JSON → window 内联(file://)              │
└─────────────────────────────────────────────────────────────────┘
```

### 1.3 核心设计原则

| 原则 | 体现 |
|---|---|
| **单文件可部署** | `vite-plugin-singlefile` 把前端打成单个 HTML,JSON 内联,离线可用 |
| **数据源极致容错** | 每 ticker 8 层降级 + 熔断器,中国 IP 环境也能稳定抓数 |
| **无未来函数** | Walk-Forward 严格时间序列,测试集用训练集的填充值/scaler |
| **前后端解耦** | 前端三层 fallback(API→fetch→window),后端挂了前端仍能看静态数据 |
| **路径集中管理** | 所有路径走 `paths.py`,禁止硬编码绝对路径 |

## 五、数据来源:八层降级机制

### 5.1 设计动机

中国 IP 直连 Yahoo Finance 频繁 429(限流)。因此**每个 ticker 独立**走最多 8 层降级,任一层成功即返回,后续层跳过。

### 5.2 八层降级顺序(`fetch_ticker_with_fallback`)

| 层 | 数据源 | 适用 ticker | 机制 |
|---|---|---|---|
| 1 | **yfinance** | 全部 | 主源;连续 2 次失败触发熔断,后续 ticker 跳过本层 |
| 2 | **新浪美股日线** | 非 `^`/非 `=` | `_fetch_from_sina` |
| 3 | **东方财富 K线** | 非 `^`/非 `=` | `curl_cffi` Chrome TLS 模拟;间隔 1.5s,重试 3 次 |
| 4 | **新浪全球期货** | 仅 GC=F / HG=F | `_fetch_from_sina_futures`(HG 缩放 ×0.01) |
| 5 | **腾讯外汇** | 仅 DXY/EUR/JPY | T+0 真 ICE DXY |
| 6 | **CBOE 官方 CSV** | 仅 VIX/VIX9D/GVZ | `_fetch_from_cboe` |
| 7 | **FRED CSV** | 利率/BTC/DXY 等 10 个 | 重试 2 次带退避;`.` 当 NaN |
| 8 | **代理因子** | GC=F→GLD(+10.75) / HG=F→CPER(×1) / GVZ→VIX(×0.5) | 代理 ticker 再走 1-7 层 |

### 5.3 熔断器

`_YF_CIRCUIT_THRESHOLD = 2`:yfinance 连续失败(异常或数据<100 行)达 2 次,后续 ticker 直接跳过第 1 层。任一成功重置计数。

### 5.4 ticker 与 FRED 清单

- **TICKER_NAMES**(24):GC=F, GLD, IAU, SGOL, DX-Y.NYB, TIP, IEF, TLT, SLV, GDX, GDXJ, SIL, ^VIX, ^GVZ, NEM, EUR=X, JPY=X, UUP, HG=F, BTC-USD, ^VIX9D, ^IRX, ^FVX, ^TNX, ^TYX。
- **FRED_SERIES**(主管道直取 7 个):DFII10, DFII5, DGS2, DGS10, DGS30, DFF, T10YIE。
- **FRED_ALTERNATIVES**(10):yfinance ticker → FRED ID 映射。

> ⚠️ **`^VIX9D` 故意不做代理**(否则 VIX 期限结构特征归零)。改映射表时务必保留此例外。

### 5.5 关键数据清洗规则

1. **只保留有金价的交易日行**(FRED 非交易日行曾导致 Regime 全失效——历史 bug)。
2. FRED 列 `.ffill()` 前向填充。
3. 数据时效校验:最新金价超过 4 天打告警(不中断)。
4. 各层要求有效行数 >100(FRED/CBOE/腾讯/新浪)或 >50 才接受。

## 六、主管道 gold_factor_v5

### 6.1 阶段总览(线性脚本,非函数式)

```
[1a] 采集 24 ticker + 7 FRED → 合并 df
[2]  因子工程(41 个候选)
[2.5] VIF 剪枝(41 → ~25-30)
[3]  标签(PREDICT_DAYS=[5,10,20,60],二分类)
[4]  Regime 识别(MA50/MA200 + V4.3 快速切换)
[5]  Walk-Forward 分类训练(每周期独立)
[5.1] 回归分支(收益预测,辅助仓位幅度)
[5.5] 信号命中率基线 + 熔断系数
[6]  8 策略回测(V1.0 → V3.0-E + 买入持有)
[6.5] Holdout 验证(125 天干净样本外)
[7]  当前预测(全量重训 + IC 加权 + V3.0-E 仓位)
[8]  输出:8 图 + Excel + 2 JSON + SQLite + 漂移快照
```

### 6.2 关键参数

| 参数 | 值 | 含义 |
|---|---|---|
| `PREDICT_DAYS` | [5, 10, 20, 60] | 四个预测周期 |
| `TRAIN_WINDOW` | 500 | 训练窗口(高波动自适应缩到 250) |
| `TEST_WINDOW` | 60 | 测试窗口 |
| `STEP` | 30 | 步进 |
| `GAP` | 10 | Purged K-fold 隔离间隔 |
| XGB/LGB | 80 棵树,深度 3,lr 0.05 | 强正则防过拟合 |
| `scale_pos_weight` | min(neg/pos, 2.0) | 类别平衡(牛市样本占 64%) |
| VIF 阈值 | 10 | 迭代剔除共线性 |
| 聚类阈值 | t=0.3(相关>0.7 同簇) | Ward 层次聚类 |
| 波动率目标 | 15% 年化 | V3.0-B 缩仓系数 |
| 止损 | 回撤>8% 空仓 3 天 | V3.0-C |
| 仓位限幅 | [-1.5, +1.5] | 最终裁剪 |
| `HOLDOUT_DAYS` | 125(~6 月) | 干净样本外验证 |

### 6.3 V3.0-E 仓位阈值表(核心策略)

| Regime | 条件 | 仓位 |
|---|---|---|
| 牛市 | P > 0.65 | 100% |
| 牛市 | P > 0.55 | 60% |
| 牛市 | P > 0.48 | 30% |
| 牛市 | P ≤ 0.48 | 0%(牛市不做空) |
| 熊市 | P < 0.35 | -100% |
| 熊市 | P < 0.45 | -50% |
| 熊市 | P ≥ 0.45 | 0% |
| 震荡 | P > 0.60 | 40% |
| 震荡 | P < 0.40 | -30% |
| 震荡 | 0.40-0.60 | 0% |

### 6.4 多周期集成权重

`softmax(IC/0.5)`,IC 为负的周期权重上限 0.15。近期实测:5日 0.18 / 10日 0.18 / 20日 0.22 / 60日 0.42(长周期主导)。

### 6.5 输出产物

| 产物 | 路径 | 消费者 |
|---|---|---|
| 8 张图 | `outputs/charts_v5/01_~08_*.png` | Excel 报告 |
| Excel | `outputs/reports/黄金多因子分析报告_V5.xlsx` | 8 sheet |
| **dashboard JSON** | `web/dashboard_data.json` + 同步到 `public/` | 前端主数据 |
| **execution JSON** | `web/execution_data.json` + 同步到 `public/` + `outputs/execution_data_latest.json` | 执行方案 |
| **SQLite** | `data/gold_signals.db` (直写,不再走 ingest_current) | 历史查询 |
| 漂移快照 | `data/drift_history.json` (上限 90 条) | 前端历史页 |

## 七、前后端交互

### 7.1 三种运行模式

| 模式 | 触发条件 | 数据来源 | 实时性 |
|---|---|---|---|
| **API 模式** | 前端探测到 `localhost:8000/api/health` 返回 ok | `/api/state` + WebSocket | 实时(WS 推送) |
| **fetch 模式** | http(s):// 协议但无 API | `./dashboard_data.json` | 30s 轮询 |
| **window 模式** | file:// 协议(离线) | `window.__DASHBOARD_DATA__`(inject_data.py 注入) | 静态 |

前端启动时 `autoDetectApi()`(2.5s 超时)探测,成功进 API 模式,失败回退。

### 7.2 API 路由全表

| 方法 | 路径 | 返回 | 数据源 |
|---|---|---|---|
| GET | `/api/health` | `{status, version, dashboard_loaded, mtimes}` | 内存 |
| GET | `/api/state` | `{dashboard, execution, fetched_at}` | JSON 缓存(mtime) |
| GET | `/api/history` | 最近 N 天 raw_data(≤250) | JSON 缓存 |
| GET | `/api/drift` | 漂移快照列表 | drift_history.json |
| GET | `/api/strategies` | 策略列表 | JSON 缓存 |
| GET | `/api/signals/recent` | 仓位变化点(≤100) | JSON 缓存 |
| POST | `/api/db/ingest` | 写 SQLite → signal_id | 写 db |
| GET | `/api/db/history` | SQLite 历史(≤3650 天) | SQLite |

### 7.3 WebSocket 机制

- **连接时**:推送 `{"type":"initial", data:{dashboard, execution}}`。
- **文件监听**:`file_watcher()` 后台任务每 2s 检查两个 JSON 的 mtime,变化时广播 `{"type":"state_update", data:{...}}`。
- **心跳**:客户端发 `{"action":"ping"}` → 服务端回 `{"type":"pong"}`。
- **断线重连**:前端 `onclose` 后 5s 自动重连。

### 7.4 静态文件托管

- `GET /` → `web/dashboard-vue3.html`(FileResponse)
- `GET /{file_path:path}` → 在 `WEB_DIR` 下解析,**带路径穿越防护**(`str(candidate).startswith(str(base))`),拒绝 `api/` 前缀和 `ws`。
- 这就是为什么单服务就能同时提供 API 和前端页面。

### 7.5 V5 参数化运行(API 触发)

### 7.6 V5.3 模型改进开关(2026-08-11 实验落地)

经八轮消融实验验证,主管道新增环境变量开关控制模型行为:

| 环境变量 | 默认 | 说明 | 实验依据 |
|---|---|---|---|
| `V5_DATA_PERIOD` | `10y` | 数据采集周期。5y=原V5(几乎全牛市);10y=含2018熊市 | **第九轮(★反直觉)**:10y下WF IC近零(+0.123→-0.024)但Holdout夏普改善(-2.25→-1.58,首次跑赢买入持有)。熊市样本184→461天,模型从"方向预测器"变"风控择时器" |
| `V5_PURGE_GAP` | `60` | walk-forward 的 train/test 间隔天数。GAP≥N 才能消除 N 日标签泄漏 | **第八轮(★方法论修复)**:GAP=10 对60日标签有50天泄漏,实测60日IC从+0.290(泄漏)降到+0.123(真实),57%是水分。详见下表 |
| `V5_FEATURE_BLACKLIST` | `1`(开) | 特征手术:剔除7个per-feature IC诊断确认的噪声/反转特征(距FOMC/CPI天数、FOMC/CPI周、RSI14、BTC/黄金、金/纽蒙特)。24→18特征 | diagnose_model.py:这7个特征60日IC≈0或在牛/震荡完全反转。砍掉后60日IC从+0.171→+0.290(GAP=10)/+0.123(GAP=60) |
| `V5_REGRESSION_ADJUST` | `0`(关) | 回归仓位调整:关闭用R²<0的回归预测调整仓位幅度 | 回归分支R²全负(-0.09~-0.41),用它调仓位等于用噪声干预正确信号 |
| `V5_SAMPLE_AUGMENT` | `0`(关) | 熊市样本增强:熊市样本30-100天时复制补齐 | 实测IC精确相同,复制逻辑未触发(无效),保留待研究 |
| `V5_LABEL_MODE` | `abs` | 标签模式:abs=绝对涨跌(原V5) / excess=超额收益 | excess在简化实验中IC"转正",但主管道实测60日IC从+0.171恶化到-0.026,改回abs |

**GAP 标签泄漏消融实测**(第八轮,2026-08-11):

| 指标 | GAP=10(泄漏) | GAP=60(无泄漏) | 解读 |
|---|---|---|---|
| 60日 IC | +0.290 | **+0.123** | 57%是泄漏水分;真实信号仍>0.05有效 |
| 60日命中率 | 72.3% | 64.6% | "惊艳"的72%也有水分 |
| 全周期夏普 | 2.62 | 2.13 | -19%,但仍>买入持有1.26 |
| Holdout夏普 | -1.44 | **-2.25** | 泄漏在撑着,去掉后暴露真实近期表现 |

> 泄漏机理:末尾训练样本(start_idx-GAP-1)的60日标签窥探到 start_idx-GAP..start_idx+49,GAP=10时50天落入test集。GAP只影响回测验证,不影响实盘预测(每日全量重训无train/test边界)。

**生产环境推荐配置**(已设为默认):
```bash
V5_DATA_PERIOD=10y V5_PURGE_GAP=60 V5_FEATURE_BLACKLIST=1 V5_REGRESSION_ADJUST=0 V5_SAMPLE_AUGMENT=0 V5_LABEL_MODE=abs
```

**回退到原V5行为**(5y数据,全部关闭,GAP=10历史值):
```bash
V5_DATA_PERIOD=5y V5_PURGE_GAP=10 V5_FEATURE_BLACKLIST=0 V5_REGRESSION_ADJUST=1 V5_SAMPLE_AUGMENT=0 V5_LABEL_MODE=abs
```

> ⚠️ **重要教训**:九轮实验中,前六轮(权重/标签/阈值/样本)的简化消融实验结论都被主管道实测推翻;第七轮(特征手术)有效但IC被GAP=10泄漏高估;第八轮(GAP修复)暴露真实IC;第九轮(10y数据)IC近零但Holdout改善——**IC≠策略表现,风控择时可以IC近零但夏普为正**。简化实验的 walk_forward 省略了自适应窗口/Regime-conditional 训练,IC 估计偏乐观。**任何模型改动必须主管道实测验证,不能只信消融脚本。** 详见 `TOOLS.md` 和 `tests/ablation_*.py`。

### 9.3 SQLite schema(`data/gold_signals.db`)

**signals 表**(22 字段):

```sql
id | run_at | base_date | gold_price | regime | position | weighted_prob

v3e_sharpe | v3e_max_dd | v3e_annual_ret | v3e_win_rate

```

**alerts 表**:`id | alerted_at | alert_type | severity | title | detail | metric_value | baseline_value`。

**parse_pct 智能解析**(关键逻辑,曾有 bug):
- `"59.6%"` → 0.596(带 % 除 100)
- `"2.44"` → 2.44(纯数字保持)
- `-6.9%"` → -0.069
- 判断依据:**只看字符串里有没有 `%`**,不看数值大小(早期用 `abs(n)>1.5` 判断导致夏普 2.44 被误除 100)。

**pos_factor 计算**:`hit_rate_20d - wf_base` 的偏离分档:
- 偏离 < -0.25 → 0.2
- 偏离 < -0.15 → 0.5
- 偏离 < -0.05 → 0.8
- 其他 → 1.0

## 十一、指标字典(含义 + 计算 + 来源)

### 11.1 决策类指标

| 指标 | 含义 | 计算方式 | 来源 |
|---|---|---|---|
| **加权集成概率** | 模型看多概率 | `Σ(w_horizon × P_horizon)`,权重 = softmax(IC/0.5) | V5 [5]+[7] |
| **Regime 市场状态** | 牛/震荡/熊 | MA50/MA200 均线排列 + 快速切换触发 | V5 [4] |
| **建议操作** | 加仓/持有/减仓/清仓 | V3.0-E 阈值表(见 6.3) | V5 [7] |
| **目标仓位%** | 建议投入比例 | Regime 分层 + 波动率靶向 + 熔断 + 止损,clip[-1.5,1.5] | V5 [7] |

### 11.2 回测类指标

| 指标 | 含义 | 计算 | 参考 |
|---|---|---|---|
| **年化收益** | 年均回报 | 几何年化 | - |
| **夏普 SHARPE** | 风险调整收益 | (年化收益-无风险) / 年化波动 | >1.0 合格,>1.5 优秀 |
| **最大回撤 MAX DD** | 历史最大亏损 | 峰谷最大跌幅 | <20% 稳健 |
| **CALMAR** | 收益/回撤比 | 年化收益 ÷ 最大回撤 | >1.0 不错 |
| **胜率** | 盈利占比 | 盈利天数 / 总天数 | >50% |
| **年化波动 VOL** | 收益波动 | 日收益标准差 × √252 | - |

### 11.3 模型质量指标

| 指标 | 含义 | 计算 | 参考 |
|---|---|---|---|
| **ACC** | 方向准确率 | 预测方向 == 实际方向 的比例 | >55% 不错 |
| **AUC** | 分类区分力 | ROC 曲线下面积 | >0.55 有效 |
| **IC** | 信息系数 | 预测概率与实际收益的 Spearman 相关 | >0.05 有效 |
| **DIR ACC** | 方向准确率(回归分支) | 同 ACC,来自回归模型 | >55% |
| **衰减 Decay%** | 过拟合程度 | `1 - OOS_Sharpe / Full_Sharpe` | <30% 健康,>50% 危险 |

### 11.4 风险类指标(模拟器)

| 指标 | 含义 | 计算 |
|---|---|---|
| **期望终值** | 1000 次模拟平均 | GBM 路径均值 |
| **VaR 95%** | 最坏 5% 亏损 | 第 5 百分位 |
| **破产概率** | 本金亏≥50% 概率 | 路径中触及强平线的占比 |
| **最大盈亏** | 极端值 | 路径极值 |

### 11.5 归因类指标(Brinson)

| 指标 | 含义 | 计算 |
|---|---|---|
| **Alpha** | 超额收益 | 策略总收益 - 买入持有收益 |
| **配置效应** | Regime 择时贡献 | `Σ (实际仓位 - 基准仓位) × 金价日收益` |
| **选股效应** | 标的选择贡献 | `Σ 基准仓位 × (实际日收益 - 金价日收益)` |
| **交互效应** | 协同贡献 | Alpha - 配置 - 选股 |

### 11.6 前端计算的告警规则(WallView)

| 告警 | 触发条件 | 级别 |
|---|---|---|
| 命中率下滑 | hit_rate vs wf_base 偏离 > -20% / > -10% | HIGH / MEDIUM |
| 概率漂移 | prob_drift > 0.20 | HIGH |
| 因子结构变化 | TOP5 特征进出 | MEDIUM |
| IC 漂移 | 60d IC 变化 > 0.03 | MEDIUM |
| 夏普漂移 | 夏普变化 > 0.1 | MEDIUM |

## 十五、已知技术债与陷阱

### 15.1 已知技术债(来自 ARCHITECTURE.md)

- [ ] V5 脚本不支持命令行参数(调优走环境变量)
- [ ] 告警 webhook 内存存储(重启失效,应改 SQLite alerts 表)
- [ ] 多标的(SILVER/COPPER/BTC)只有简化数据,未跑 ML
- [ ] Walk-Forward 视图复用 drift_history,无真正 WF 滚动窗口数据
- [ ] 事件回测类型有限(只有 FOMC/CPI/Regime)
- [ ] 移动端未优化
- [ ] 主题色切换未实现

### 15.2 已知模型局限

- **回归分支失效**:R²全负(-0.09~-0.41)。**已关闭**(`V5_REGRESSION_ADJUST=0`),不再用回归预测调仓位。
- **多头偏见**:训练样本牛市占 64%(829/182),模型结构性偏多。八轮实验已排除权重/标签/样本增强;**特征手术有效**(60日IC +0.171→+0.123,已修GAP泄漏),但熊市IC仍为nan(样本不足未根治)。
- **GAP泄漏已修**:历史 GAP=10 对60日标签有50天泄漏,60日IC虚高57%(+0.290→+0.123)。**生产已改 GAP=60**(`V5_PURGE_GAP=60`),报出的IC/夏普现为无泄漏真实值。GAP只影响回测验证,不影响实盘预测。
- **命中率语义**:命中 = (概率>0.5 的方向) == (实际方向),不是"上涨占比"。
- **简化消融实验不可信**:`tests/ablation_*.py` 的 walk_forward 省略了主管道的自适应窗口/Regime-conditional,IC 偏乐观(标签实验中简化版IC=+0.096,主管道实测-0.026)。**模型改动必须主管道实测**。

### 15.3 八轮实验验证排除的方向(不要重复尝试)

| 方向 | 为什么不行 | 实验脚本 |
|---|---|---|
| 调权重(砍负IC周期) | Holdout全方案IC负,牛市集中投注熊市反噬 | tests/ablation_weights.py |
| 改标签(超额收益) | 主管道60日IC从+0.171恶化到-0.026 | tests/ablation_labels.py |
| 搜索最优阈值 | 训练期搜索过拟合,Holdout更差 | tests/ablation_thresholds.py |
| 熊市样本复制 | IC精确相同,复制逻辑未触发 | V5_SAMPLE_AUGMENT |

> **第八轮(GAP修复)是有效方向**:不是排除项,而是方法论修正。GAP=10→60 消除了60日标签50天泄漏,真实60日IC=+0.123(之前+0.290有57%水分)。已设为生产默认。

- **回测 vs 实盘差异**:回测用 WF 概率(30日更新),实盘每日全量重训;路径不同但参数一致。GAP 只影响回测验证,不影响实盘。

### 15.3 开发陷阱

| 陷阱 | 说明 |
|---|---|
| **parse_pct 只看 % 字符** | 不要用数值大小判断是否百分数(夏普 2.44 会被误除 100) |
| **ChartBox option 必须是函数** | 不能用 computed,否则 watchEffect 调用报错 |
| **`^VIX9D` 不做代理** | 改映射表时保留此例外,否则期限结构特征归零 |
| **FRED 非交易日行** | 必须只保留有金价的行,否则 Regime 全失效 |
| **launchd Weekday 映射** | macOS 1=周一...7=周日,Weekday 2-6 = 周二~六 |
| **inject_data NaN 剔除** | JSON 标准不允许 NaN,inject 和测试双重防护 |
| **ingest_current.py 已弃用** | V5 直写 SQLite,不要在新链路调用 |
| **中文字体回退链** | matplotlib: PingFang SC(macOS)→Noto Serif SC(Linux);ReportLab: Songti/STHeiti .ttc subfontIndex。改渲染代码保持此链 |
| **简化消融实验不可信** | `tests/ablation_*.py` 的 walk_forward 省略了自适应窗口/Regime-conditional,IC偏乐观。模型改动必须主管道实测(abs vs 改后对比) |
| **数据漂移** | 多次跑管道间隔数小时,数据源可能返回新交易日数据,跨运行横向对比不完全公平 |

## 十六、开发工作流(接手指南)

### 16.1 改了不同东西,要做什么

| 改动 | 必做验证 |
|---|---|
| 任何 Python 代码 | `python3 -m compileall -q src` + 受影响模块跑通 |
| JSON 字段/路径/数据源映射 | `PYTHONPATH=src .venv/bin/python3 -m pytest tests/ -q` |
| 主管道逻辑 | 手动跑 `gold_factor_v5`,检查 web/*.json + 图表 + SQLite |
| 前端组件 | `npm run build` + `inject_data.py` + 浏览器逐 Tab 验证 |
| 前端文案 | 同步 `i18n/index.ts` 中英两套 |
| 路径 | 只改 `paths.py`,搜索全项目确认无硬编码 |
| data/ 下状态文件 schema | 保持向后兼容,冒烟测试会校验 |

### 16.2 新增一个前端 Tab 的步骤

1. 在 `src/views/` 新建 `XxxView.vue`。
2. `App.vue` 的 `views` 字典注册懒加载:`xxx: () => import('@/views/XxxView.vue')`。
3. `App.vue` 的 `tabs` 数组加 `{ key:'xxx', tkey:'nav.xxx' }`(显式)或加入某 group 的 tabs。
4. `i18n/index.ts` 加 `nav.xxx` 中英文。
5. `npm run build` + `inject_data.py` + 部署。

### 16.3 新增一个 API 路由的步骤

1. `api_server.py` 加 `@app.get("/api/xxx")`。
2. 数据来源选:JSON 缓存(`_safe(_dashboard_cache)`)或 SQLite(`db.query_xxx()`)。
3. 返回前用 `_safe()` 剔除 NaN。
4. 重启 `start_api.sh restart`。
5. 前端 `useDashboardData.ts` 加 fetch 封装。

### 16.4 新增一个数据源 ticker 的步骤

1. `data_fetcher.py` 的 `TICKER_NAMES` 加映射。
2. 若有 FRED 等价,加 `FRED_ALTERNATIVES`;若有代理,加 `PROXY_FALLBACK`。
3. `gold_factor_v5.py` 的因子工程部分加入新因子计算。
4. 跑 `test_fetcher_mappings` 确认映射一致性。
5. 跑主管道确认数据到位。

### 16.5 调试技巧

- **看数据流**:`rtk proxy python3 -m gold_model.gold_factor_v5` 跑一次,检查 `web/*.json`。
- **看后端日志**:`tail -f /tmp/gold_api_server.log`。
- **看每日日志**:`logs/daily_*.log`,搜 `=====` 时间戳。
- **查 SQLite**:`sqlite3 data/gold_signals.db "SELECT run_at, regime, position, weighted_prob FROM signals ORDER BY id DESC LIMIT 5"`。
- **前端调试**:Chrome DevTools,看 Network 的 `/api/state` 响应;Console 看 `[data]`/`[ws]` 日志。
